# 05: Enter progress from the Unit card

**What to build:** On the Unit card's Items disclosure, an Administrator sees each Item's Progression and latest entry (value, author, date), types a whole number from 0 to 100 and an optional note into an inline "Enter progress" form, and the Item updates in place. The form is disabled with a hint on an Item with no Assignment. A History disclosure lists every entry newest first. A later entry may be lower than the last.

Routes: `POST /projects/:id/items/:itemId/entries { value, note? }`, `value` an integer 0 to 100, `note` optional, trimmed, 1 to 200 characters; 409 `ITEM_UNASSIGNED` without an Assignment; one transaction inserts the entry and sets the Item's stored Progression to its value; author fields from the Administrator's token (`enteredByKind` administrator, `enteredById` the subject, `enteredByName` the email); 201 with the Unit's Items. `GET /projects/:id/units/:unitId/items` gains `latestEntry: { value, note, enteredByName, createdAt } | null`. `GET /projects/:id/items/:itemId/entries` returns `{ id, value, note, enteredByKind, enteredByName, subcontractorName, createdAt }` newest first.

Spec: `.scratch/items-and-progression/spec.md`. ADR-0008 applies.

**Blocked by:** 04 (Assign Items to a Subcontractor, in bulk and singly)

**Status:** complete

- [x] Enter progress returns 201 and the mocked transaction shows the entry insert and the Progression update together; a lower value than the previous one is accepted; covered at the HTTP seam
- [x] 400 for a non-integer, negative or over-100 value or a note over 200 characters; 409 `ITEM_UNASSIGNED` without an Assignment; 404 for an Item of another Project
