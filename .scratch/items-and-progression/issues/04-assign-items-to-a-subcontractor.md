# 04: Assign Items to a Subcontractor, in bulk and singly

**What to build:** From a Catalogue Item's row, an Administrator chooses "Assign", makes the Unit selection, picks a Subcontractor from a search of the Directory, and sees "Will assign N; M already assigned elsewhere will be skipped"; ticking "Reassign Items already assigned elsewhere" changes that to "reassigned". Choosing "Unassign" instead of a Subcontractor removes the Assignment from every selected assigned Item. On the Unit card, an Administrator sets, changes or clears one Item's Subcontractor from a select. In the Directory, deleting a Subcontractor that holds Assignments is refused with the count. Nothing about an Item's Progression or history changes when its Assignment does.

Routes: `POST /projects/:id/assignments { catalogueItemId, subcontractorId: string | null, reassign?: boolean, blockIds?, storeyIds?, unitTypeIds? }`: with a Subcontractor, assigns every selected unassigned Item and, with `reassign`, every Item assigned elsewhere too, skipping Items already assigned to the target; with `null`, unassigns every selected assigned Item; 404 for an unknown Subcontractor; 200 with the full Project and `meta: { assigned, skipped }`. `PATCH /projects/:id/items/:itemId { subcontractorId: string | null }` for one Item. `GET /projects/:id/units/:unitId/items` is introduced here in its minimal shape (`id`, `catalogueItemId`, `name`, `subcontractor`, `assignedAt`, `progression`) and the Unit card gains an Items disclosure showing it; ticket 05 adds entries. `DELETE /subcontractors/:id` gains 409 `SUBCONTRACTOR_HAS_ASSIGNMENTS` with `details: { itemCount }`.

Spec: `.scratch/items-and-progression/spec.md`. ADR-0003 and ADR-0008 apply.
